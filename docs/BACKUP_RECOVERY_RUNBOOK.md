# 备份与恢复运行手册（待批准执行）

> 状态：只定义上线前门禁和演练证据；不包含服务器密码、云端凭据或可直接执行的生产删除命令。未经 B02、B06 和部署窗口批准，不运行 Docker、不生成生产备份、不恢复任何服务器数据。

## 目标与口径

- 备份对象：项目独立 MySQL 数据、`ingest-data` 中的 SQLite outbox/state、部署配置版本与恢复清单。
- 不备份：镜像缓存、可重新构建前端产物、Redis 作为唯一业务事实源、任何 `.env` 明文密钥。
- 项目长期总盘上限仍为 **10,000,000,000 bytes**；备份保留策略必须计入该口径或放入已批准的异地目标。
- 恢复只能恢复到新的、隔离的 GameBoi 运行时，禁止覆盖服务器上其他项目的 MySQL、Redis、卷或网络。

## 执行前门禁

1. B02：确认异地备份位置、所有权、加密和保留天数。
2. B06：确认 Docker/网络/磁盘配额与维护窗口；Compose 容器已通过独立环境验证。
3. 记录当前 Compose 配置 hash、镜像 digest、MySQL schema 版本、outbox 未确认数量、可用磁盘和预估备份大小。
4. 检查备份目标剩余空间，确保备份失败不会触发自动删除业务数据。
5. 备份过程中 ingest profile 必须停止新增采集；未 ACK outbox 仅复制，不确认、不清空。

## 恢复演练验收

恢复演练必须在隔离主机或独立本机环境中完成，并记录：

- MySQL 可从空卷恢复并通过 Flyway 历史/业务表计数检查；
- outbox/state 文件恢复后，未 ACK eventId 仍保持原值；
- 对同 eventId 重投得到幂等 receipt，不重复写文章；
- 已发布公开 API 可读，未发布内容仍是 404；
- 管理员审核记录、来源暂停状态和容量门禁保留；
- 恢复后资源上限、日志保留和独立网络仍生效；
- 明确恢复点、耗时、失败点和回滚方式。

没有上述演练证据，不得声称具备上线恢复能力。
